# Space Tracker 需求文档（MVP）

## 1. 背景

当前使用 Disk Sniffer 一类工具时，扫描完成后能够看到所有目录的当前占用，但每次打开工具看到的基本是同一张“静态地图”。真正需要解决的问题是：

- 不必反复关注长期稳定的 Windows、程序安装目录；
- 能知道自上次扫描以来哪些目录增长了多少、增长速度多快；
- 增长结果能继续拆到子目录，而不是只停留在父目录；
- 符号链接、目录联接点等重定向目录必须识别、标记并避免重复计算；
- 找到可处理对象后，未来可以把目录迁移到其他磁盘并建立符号链接。

## 2. 产品目标

Space Tracker 是一个面向 Windows、优先服务 Agent 的 CLI 磁盘空间追踪工具。它将“当前占用”和“增长占用”作为两个独立视图：

1. 当前占用：查看某次快照中各层目录、文件和链接的实际占用。
2. 增长占用：比较同一根目录的两次快照，输出增长最多的目录、新增大文件、删除文件和增长速度。
3. 可审计：每次扫描产生可读、可留存、可复算的快照文件，不依赖后台服务。

## 3. 用户与典型流程

主要用户是希望主动管理 C 盘的个人用户，也包括可以调用 CLI 的 Agent。

典型流程：

```text
首次扫描 C:\Users\YourName\AppData
        ↓
若干天后再次扫描同一路径
        ↓
查看增长目录排序和增长速度
        ↓
对某个增长目录继续查看直接子目录/文件
        ↓
确认是否清理、迁移或建立链接
```

## 4. MVP 范围

### 4.1 必须支持

- Windows 目录递归扫描。
- 保存扫描根目录、扫描时间、总大小、文件数、目录数、错误数。
- 保存每个文件和目录的相对路径、大小、类型、修改时间。
- 目录大小为其可访问普通文件大小的递归汇总。
- 识别 Reparse Point，包括目录联接点和符号链接。
- 默认不跟随 Reparse Point，避免同一份数据重复计算或形成循环。
- 对链接记录原路径、类型、目标路径（能够解析时）和“未跟随”状态。
- 查询同一根目录最近两次快照的 Delta。
- 输出所有层级的增长目录，而不只输出根目录的直接子目录。
- 输出增长字节数、增长百分比和按时间折算的增长速度。
- 查看指定快照中某个目录的直接子目录和直接文件。
- 输出 JSON，便于 Agent 消费；同时提供简洁的人类可读表格。
- 对无权限、路径消失、文件正在被占用等问题记录错误并尽可能继续扫描。

### 4.2 明确不放进 MVP

- 自动删除文件。
- 自动迁移目录。
- 自动创建符号链接或目录联接点。
- 常驻后台服务、定时任务和系统通知。
- GUI、Treemap 和图形化报表。
- 常驻数据库服务；第一阶段使用 zstd 压缩的 `.base.zst`/`.delta.zst` 文件，便于本地备份和增量保存。
- 无上限的并行扫描调度；并行化必须受控，并以结果一致性、内存占用和真实扫描耗时为准。

## 5. CLI 草案

无参数启动进入轻量交互式 CMD，不依赖 TUI 库：

```text
space_tracker.exe
  扫描路径             [默认 C:\]
  数据存放路径         [默认 exe 所在目录]
  增长提示阈值         [默认 100M]
```

交互模式先对目标目录做一次不跟随链接的轻量条目统计，建立进度分母；正式扫描时动态显示百分比和已处理条目数。结束后先显示当前占用重点路径，最后固定输出增长提醒。增长提醒只保留超过阈值且没有更深层超阈值子目录覆盖的目录，避免同一份增长在父子路径重复出现；提醒包含两次扫描之间的时间段和增长字节数，按变化量从小到大呈现。阈值支持 `B`、`K`、`M`、`G`、`T` 等二进制单位后缀。

有参数时继续使用以下 CLI：

```text
space_tracker scan <ROOT> [--store <DIR>] [--compact] [--json]
space_tracker history [--root <ROOT>] [--store <DIR>] [--json]
space_tracker delta [--root <ROOT>] [--current <SNAPSHOT>] [--store <DIR>]
                     [--limit <N>] [--min-bytes <N>] [--json]
space_tracker children [--root <ROOT>] [--snapshot <SNAPSHOT>]
                       --path <PATH> [--store <DIR>] [--limit <N>] [--json]
space_tracker query [--root <ROOT>] [--snapshot <SNAPSHOT>]
                    --path <PATH> [--store <DIR>] [--limit <N>] [--json]
space_tracker links [--root <ROOT>] [--snapshot <SNAPSHOT>]
                    [--store <DIR>] [--json]
```

CLI 默认快照目录为当前目录下的 `.space-tracker`；交互模式默认使用 exe 所在目录。实际使用 C 盘时建议显式指定 H 盘目录，例如：

```powershell
space_tracker scan C:\Users\YourName\AppData --store D:\space-tracker\snapshots --json
space_tracker delta --root C:\Users\YourName\AppData --store D:\space-tracker\snapshots --json
```

## 6. 验收标准

### A. 快照和当前占用

- 对一个小型测试目录扫描后，根目录总大小等于普通文件大小之和。
- `children` 只返回指定目录的直接子项，并按大小排序。
- `.base.zst` 可以独立恢复完整快照；`.delta.zst` 可以依赖同一根目录的 manifest 和前置基线恢复逻辑快照，不依赖运行中的扫描程序。
- 指定数据目录后，程序会创建 `space-tracker` 子目录；首份扫描写 `.base.zst`，后续扫描写 `.delta.zst`。
- 交互式进度基线与正式扫描均不跟随 Reparse Point；百分比基于已处理文件和目录数，文件变化时允许最终值以实际扫描结果为准。
- 有参扫描和交互式进度基线使用受控 Rayon 并行；交互式正式扫描保留顺序回调，确保人类可读的进度输出稳定。

### B. Delta 和增长视图

- 在两次扫描之间新增或扩大文件后，`delta` 能列出对应文件和所有受影响的父目录。
- 目录 Delta 按增长字节数降序排列。
- 交互式增长提醒隐藏已被超阈值子目录覆盖的父目录，并保留路径前缀边界正确性。
- 同一路径但根目录不同的快照不能被错误比较。
- 没有上一份同根目录快照时，CLI 明确提示而不是给出伪造的零增长。

### C. 链接与重复计算

- 测试目录中的目录联接点/符号链接被列入链接清单。
- 默认扫描不进入链接目标；链接目标中的文件不会被重复计入根目录总大小。
- 链接目标可解析时被记录；无法解析时保留链接本身并记录原因。
- 现实基线中 `C:\Users\All Users -> C:\ProgramData` 这类目录不会造成重复计数。

### D. 真实基线比对

用之前的手动探查结果做数量级校验，重点检查：

| 路径 | 手动探查参考值 |
|---|---:|
| `C:\Users` | 约 57.79 GB |
| `C:\Users\YourName\AppData` | 约 48.50 GB |
| `C:\Users\YourName\AppData\Local` | 约 29.74 GB |
| `C:\Users\YourName\AppData\Roaming` | 约 18.48 GB |
| `C:\Windows` | 约 30.46 GB |
| `C:\Program Files` | 约 23.78 GB |
| `C:\Program Files (x86)` | 约 13.22 GB |
| `C:\ProgramData` | 约 6.04 GB |

这些数值用于发现扫描口径差异，不要求与 Disk Sniffer 百分之百一致；差异必须能解释为权限、硬链接、压缩、稀疏文件或扫描时点不同。

## 7. 后续版本方向

1. 在不改变 `.base.zst`/`.delta.zst` 契约的前提下，增加版本化二进制载荷和目录索引。
2. SQLite 或 redb 作为可选的高频查询索引层，并评估其额外空间和打包成本。
3. 增长树：在 Delta 结果中交互式下钻，而非只列平铺路径。
4. 链接目标显示、硬链接身份和重复数据的更精确归因。
5. 安全的“迁移到其他盘 + 创建链接 + 回滚检查”工作流。
6. 定时扫描和低空间提醒。
